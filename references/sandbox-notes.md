# 沙箱与受限网络降级策略

很多 AI 编程代理（CLI agent）运行在**受限网络环境**中：Bash 可能没有直接外网，
或只是"部分连通"——国内站点可达而海外站点全部超时；且不同环境可用的命令行工具
不同（常见：无 `curl`，但有 `wget` / `python3`）。本文件定义此环境下的检索降级
路径，让调研照常完成，而不是反复撞墙。

## 判断网络环境

任务开始时低成本探测一次。**探测对象是你马上要访问的站点，而不是笼统地"有没有网"**——
"部分连通"环境下，能连 A 站不代表能连 B 站。

探测命令按可用性依次尝试，保证在无 curl 的极简环境也能执行（把示例 URL 换成目标站点）：

```bash
# 1) curl（若存在）
curl -s -m 5 -o /dev/null -w "%{http_code}\n" https://www.baidu.com
# 2) wget（BusyBox 环境常见，无 curl 时用这个）
wget -q -T 5 -O /dev/null https://www.baidu.com && echo OK || echo FAIL
# 3) python3 兜底（纯标准库，几乎任何环境可用）
python3 -c "import urllib.request; print(urllib.request.urlopen('https://www.baidu.com', timeout=5).getcode())"
```

失败/超时 → 该目标按"不可直连"处理，改走下方降级路径，**之后不要再反复试直连**；
成功 → 可直连，但换一个新域名时可能需要重新判断。

## 降级路径（按优先级）

### 1. MCP 检索工具（首选）
沙箱内通常预先配置了走宿主网络的 MCP 工具，例如：

- 网页搜索：Tavily（`tavily_search`，支持 `search_depth: advanced`、时间范围、域名过滤）
- 网页抓取：Tavily extract（`tavily_extract`）或其他已配置的 MCP 抓取工具
- 平台专用：小红书/Reddit/B站等平台工具（若有配置）

**检索主力用搜索工具；网页正文读不动时，优先改用 MCP 抓取工具**——它走服务端
网络抓取，不受本地网络连通性的限制。

### 2. Reader 类服务（备选，需先探测）
Jina Reader（`https://r.jina.ai/<URL>`）等 Reader 服务可作为抓正文的备选通道。
注意：**这类服务在部分网络中不可达**（例如被 DNS 污染、连接超时），使用前先探测
一次；不通就立即换通道，不要重试。

### 3. 宿主浏览器
若 agent 配有浏览器工具，可用来访问需要登录态或强 JS 渲染的页面。

### 失败重试规则
- 同一个 URL 最多用两种通道各试一次（搜索工具摘要 → 抓取工具全文），
  两种都失败就放弃该来源并记录，**不要循环重试**。
- 抓取工具返回的是转码文本，引用数据前注意核对数字没有被截断（长 PDF 经常被截）。

### 明确不做的尝试
- ❌ 反复直连重试（浪费时间且注定失败）
- ❌ 因为网络限制而放弃标注来源（宁可少写一个数字）
- ❌ 用"我记得大概是多少"替代检索

## 链接核查的降级

`scripts/check_links.py` 需要直连网络访问待核查的目标站点。分两种情形：

- **完全无法联网**：跳过运行，在交付说明中注明"链接可达性未在线核查"。
- **部分连通**：可以运行。脚本会把“未能核实（NET）”与“真失效（DEAD）”
  分开标注；**NET 是“未能核实”（连接超时、DNS 失败、地址异常等），不是死链**，
  转述时不要写成“失效”，待网络环境改善后可重跑。

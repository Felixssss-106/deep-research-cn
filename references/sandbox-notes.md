# 沙箱环境降级策略

很多 AI 编程代理（CLI agent）运行在**沙箱中：Bash 没有直连外网**。
直接 `curl`、`gh`、`pip install` 都可能失败或超时。本文件定义此环境下的检索降级路径，
让调研照常完成，而不是反复撞墙。

## 判断是否在沙箱中

任务开始时可以低成本探测一次：发起一个轻量请求并观察是否网络超时
（例如 `curl -s -m 5 -o /dev/null -w "%{http_code}" https://www.baidu.com`）。
失败/超时即按沙箱模式执行，**之后不要再反复试直连**。

## 降级路径（按优先级）

### 1. MCP 检索工具（首选）
沙箱内通常预先配置了走宿主网络的 MCP 工具，例如：

- 网页搜索：Tavily（`tavily_search`，支持 `search_depth: advanced`、时间范围、域名过滤）
- 网页阅读：web_reader / Jina Reader（`https://r.jina.ai/<URL>`）等 Reader 类服务
- 平台专用：小红书/Reddit/B站等平台工具（若有配置）

**检索主力用搜索工具；网页正文读不动时，一律改走 Reader 类服务重试一次。**

### 2. 失败重试规则
- 同一个 URL 最多用两种通道各试一次（搜索工具摘要 → Reader 全文），
  两种都失败就放弃该来源并记录，**不要循环重试**。
- Reader 返回的是转码文本，引用数据前注意核对数字没有被截断（长 PDF 经常被截）。

### 3. 明确不做的尝试
- ❌ 反复 `curl` 直连（浪费时间且注定失败）
- ❌ 因为网络限制而放弃标注来源（宁可少写一个数字）
- ❌ 用"我记得大概是多少"替代检索

## 链接核查的降级

`scripts/check_links.py` 需要直连网络。沙箱模式下跳过运行，
改为在交付说明中注明：**"本次调研在沙箱环境完成，链接可达性未在线核查。"**

## 附：这个文件本身来自实战

以上规则提炼自真实的沙箱调研任务：Bash 直连全部超时，改走 MCP 搜索 + Reader
后完成两份完整市场报告（网文、微短剧），全部关键数字带来源。
如果你维护某个 agent 的 skill，建议把本文件一并打包——
它解决的是"agent 有检索能力但不知道自己没网"的隐性浪费。
